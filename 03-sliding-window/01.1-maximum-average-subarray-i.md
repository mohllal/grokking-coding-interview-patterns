# Maximum Average Subarray I

## Problem description

Given an integer array `nums` consisting of `n` elements, and an integer `k`, find a contiguous subarray whose length is equal to `k` that has the maximum average value, and return that value.

Answers within `10^-5` of the actual answer are accepted.

## Examples

**Example 1:**

```plaintext
Input: nums = [1, 12, -5, -6, 50, 3], k = 4
Output: 12.75000
Explanation: Maximum average is (12 - 5 - 6 + 50) / 4 = 51 / 4 = 12.75
```

**Example 2:**

```plaintext
Input: nums = [5], k = 1
Output: 5.00000
```

## Constraints

- `n == len(nums)`
- `1 <= k <= n <= 10^5`
- `-10^4 <= nums[i] <= 10^4`

## Hints

<details>
<summary>Hint 1</summary>

Every candidate window has the same width, so dividing by `k` does not change which window wins. Find the maximum sum and divide once at the end.

</details>

<details>
<summary>Hint 2</summary>

`nums[i]` can be negative, so the answer itself can be negative. What does that mean for the value you start the running maximum at?

</details>

## Solution

### Intuition

Because every window is exactly `k` wide, the division by `k` is a monotonic transformation — the window with the largest sum is also the window with the largest average. So track the maximum **sum** with a fixed sliding window and divide once at the end.

The subtlety is the seed. Negative inputs are allowed, so an array like `[-1]` has a genuinely negative answer. Starting the running maximum at `0` would return `0.0` for that input, which is not the average of any window at all.

```plaintext
index      0   1   2   3   4   5        k = 4
value      1  12  -5  -6  50   3

           └───────────┘                sum = 2                   avg = 0.5
               └───────────┘            sum = 2 - 1 + 50 = 51     avg = 12.75  ← maximum
                   └───────────┘        sum = 51 - 12 + 3 = 42    avg = 10.5
```

### Algorithm

1. Walk `window_end` across the array, adding each value to `window_sum`
2. Once the window holds `k` values, compare `window_sum` against the running maximum
3. Subtract `nums[window_start]`, advance `window_start`, and continue
4. Divide the maximum sum by `k` at the end

### Complexity analysis

- Time complexity: $O(n)$ — each value enters and leaves the window exactly once.
- Space complexity: $O(1)$ — only the running sum and maximum are stored.

```python
from typing import List


class Solution:
    def find_max_average(self, nums: List[int], k: int) -> float:
        # nums may be entirely negative, so 0 is not a safe starting maximum
        maximum_sum = float("-inf")

        window_start = 0
        window_sum = 0
        for window_end in range(len(nums)):
            window_sum += nums[window_end]

            if window_end >= k - 1:
                maximum_sum = max(maximum_sum, window_sum)
                window_sum -= nums[window_start]
                window_start += 1

        # every window has width k, so dividing once at the end is enough
        return maximum_sum / k
```

## Relationship to [Maximum Sum Subarray of Size K](./01-maximum-sum-subarray-of-size-k.md)

Same fixed window, same slide, same running sum. Two differences matter:

- That problem guarantees **positive** numbers, so seeding the maximum with `0` is harmless. Here negatives are allowed, so the seed must be `float("-inf")`.
- The answer is divided by `k`. Since `k` is constant across every candidate, the division can happen once at the end rather than inside the loop — which also avoids accumulating floating-point error.
